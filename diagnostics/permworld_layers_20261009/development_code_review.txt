PermWorld 编码 × 架构开发评价：只读代码审查
日期：2026-10-10（America/Los_Angeles）

范围与状态
审查 evaluation.py、common.py、training.py、冻结 protocol.json，以及它们
直接复用的 encoding/core.py 和 data.py。没有修改冻结代码、指标或协议，
没有运行 GPU、训练或重复既有验证。以下是实现与解释审查，不是对尚在
运行的开发结果作效应判断。未发现阻断当前预定开发评价的配对或公式问题。

1. 两编码共享对象、标签和训练曝光
数据只生成一次底层排列 p；每个动作先计算 q=transform(p, action)，再
计算公共 labels(q)，最后分别编码同一个 q。两编码使用同一个 data.npz、
长度数组、标签数组、轨道划分和 batch_indices.npy。训练均读取 identity
动作，答案与 EOS 的监督位置和更新预算一致；没有按编码重新生成答案。
规范轮换记号通过分隔符替换及排序改变序列，两编码长度均断言为 2*n+4。
故本设计没有混入编码间序列长度差，但编码效应仍包括边界标记、分隔符
身份和排列顺序，不能归因于其中某一个因素。

本开发单元只有四个已训练任务和两条评价关系：下降—逆下降（正确取逆、
错误补值）及峰—谷（正确补值、错误取逆）。数据保存其余标签用于统一
数学构造，不等于已完成十六任务、八关系的正式确认。

2. 答案分层与固定长度评价
选择函数的联合键为 [长度、左侧原答案、右侧原答案、右侧补值答案、
右侧取逆答案]；在固定长度内保留计数至少为 3 的联合答案单元。fit/test
掩码在 architecture/encoding/initial-or-trained 的循环外生成，同一 split
内所有条件共用掩码。掩码不依赖表征、准确率或指标结果。fit/test 分别
使用各自的标签组均值中心化，跨 split 并不声称使用相同样本或均值。
各长度单独计算后按固定等权汇总；未定义单元不应被重新加权为可用长度。
这是一项使用真值的测量控制；它不移除所有置信度、错误模式或非线性
答案信息。

3. 分解、编码交互及指标方向
B0=initial_correct-initial_wrong；Bt=trained_correct-trained_wrong；
change_correct=trained_correct-initial_correct；change_wrong 同理；
Delta=Bt-B0=change_correct-change_wrong。源代码检验后一恒等式。
Gamma 的方向统一为 canonical_cycle-one_line；因此
GammaDelta=Gammat-Gamma0=Gamma_correct-Gamma_wrong。
CKA、debiased CKA、邻域重叠均越大越相似；留出 Procrustes 将 NRMSE
取负后参与同一分解，故所有报告分数均是越大越相似，原误差越小越好。
不能把 Delta 的翻转自动写成训练后偏好翻转；需同时检查 Gamma0、Gammat
及正确/错误两侧变化。静态真值基线没有初始化学习增量。

4. 输入结束位置和任务提示解释
统一提取 final_norm 在 end=2*n+3 的状态；任务 token 位于 end+1，等号
位于 end+2。实际评价前向包含任务与等号 suffix，所测状态位于它们之前。
Transformer 的因果掩码和单向 GRU 阻止未来 suffix 影响该状态。已实现
的独立检查用 prefix-only 手动前向与缓存作固定容差比较；本审查没有重跑。
准确表述是“任务 token 之前、在因果上不依赖当前任务 suffix 的状态”，
不能写成“整个评价前向未提供任务 token”。各模型的权重已经受单任务
训练影响，任务前状态也不等于模型不知道任务。

5. 初始化和架构比较的可解释范围
每种架构保存真实 step-0 后复制给全部任务和两种编码，并检查参数摘要；
配对编码的同任务 dropout 起始种子及 batch 顺序一致。这与历史检查点
诊断的 C 级重建初始化不同，不能把两类身份合并表述。Transformer 与
GRU 使用不同初始化种子和参数构造，参数量也不同；架构比较是这些
预定系统的比较，不能单独识别架构、容量或初始化族的因果效应。
任务可学习性的工程门槛不保证两编码源准确率匹配；编码学习难度仍可
影响最终几何。该单元只有一个新共享数据世界，属于开发性分析，不能
把 16 个模型当作 16 个独立世界或作为已充分定功效的确认实验。

6. 输出基线与文档小问题
output_prob 是数值答案 token 0..30 范围内重新归一化的 softmax；不是
完整词表概率，也没有保留数值答案总概率质量。全文应采用这个名称与
范围解释，不能据此排除全部输出相关信息。
protocol.json 的 batch_schedule 文字继承了“all32 models”，当前实际
清单为 4任务×2编码×2架构=16模型。代码对同一保存的 schedule 读取，
没有发现由这个文字残留引起的曝光差异。冻结文件无需为措辞重算；最终
报告应说明当前 16 模型，后续协议版本可修正文档残留。
