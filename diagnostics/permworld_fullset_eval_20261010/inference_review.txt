I. Correct positions and complete supervision definitions
Both encoded input prefixes have length2n+4 (zero-based positions):
0 BOS,1 SIZE,2 n,3 encoding START,4..2n+2 numeric/delimiters,2n+3 encoding END;
task token at2n+4, equals at2n+5, true answer at2n+6, EOS at2n+7.
Thus the full supervised sequence has length2n+8.

Answer prediction must use logits[:,2n+5,:], with truth as answer-token ID rather than assuming directly that
property integers index the full vocabulary. EOS prediction uses logits[:,2n+6,:], with truth
TOKEN_TO_ID['<EOS>']. Do not predict answers from their input positions, where the true answer has already been read.
EOS statistics are teacher-forced EOS accuracy given true answers, not free-generated sequence
accuracy. Preserve that condition; do not add or average separate answer/EOS accuracies
and call the result task accuracy.

Original loss applies to logits[:,:-1]andtarget[:,1:]using full-vocabulary cross entropy, ignore=-100.
Each sample has valid targets only at answer/EOS, so combined_ce is exactly
(answer_ce + eos_ce)/2. Ignored prefix/task/equals/padding positions must never enter the denominator.
New forwards should construct positions independently from n, then check batch returns equals=2n+5 and both targets;
this can reveal off-by-one errors hidden by repeatedly reusing the same helper.
Original input concatenation can be directly checked: prefix[:2n+4] + [TASK,'=',truth,EOS].
Full-vocabulary accuracy uses argmax over all188 classes; auxiliary numeric accuracy uses only00..30,
31 token IDs, then compares with property integers0..30. It is not188-class accuracy.
Answer CE/EOS CE both use188-class logits; do not condition to31 classes before calculating original answer CE.
Units are natural-log nats, without label smoothing, temperature, or extra sample weights.

II. Numerical inference settings
Original accuracy uses torch.inference_mode(), net.eval(), and FP32 parameters, without
BF16 autocast; training BF16 autocast must not carry into diagnostics. Original device_setup
disables CUDA matmul/cudnn TF32, sets cudnn.deterministic=True, and uses2 CPU threads.
New diagnostics should use identical settings, explicitly ensuring FP32 floating parameters and disabled autocast.
Calling output logits.float() alone does not ensure internal FP32 forwards; check parameter dtype before forwarding.

Transformer uses the same accelerate wrapper and SDPA strict causal/key mask;
attention dropout is0 in eval. GRU starts from identical token+position embeddings,
uses four independent causal GRU layers, final_norm, and tied lm_head; trailing padding cannot change
earlier states. Outputs are original188-class logits, without additional softmax.

Group independent forwards by n, original data-index order, batch128, matching original validation
batch shapes to reduce floating-path differences; full supervised inputs and masks
must match. Save per-sample FP32 answer/EOS logits and independently aggregate logsumexp on CPU,

Forwards have no optimizer, backward, optimizer loading/restoration, or state updates.
If original accuracy is called for verification, it restores net.training mode; the primary independent path remains
in eval/inference_mode and must not continue extracting predictions in restored training mode.

Per-sample records should include run_id provenance (or manifest sidecar), split, sample_index,
n, integer task truth, truth_token_ID, answer/EOS positions, full-vocabulary answer/EOS
logits, and full-vocab/numeric/EOS predictions, not just precalculated aggregate metrics.
NPZ should specify188-dimensional vocabulary order and FP32 dtype; sidecars record original checkpoint/data/source/protocol
SHAs and new diagnostic-code digests. Per-sample CE may also be saved, but independent aggregation must recompute
from original logits to avoid two implementations sharing one wrong scalar.

Independent verification first checks complete unique indices and three length counts per split, then recomputes from logits
per-n and sample-weighted overall accuracies/CE. Counts per n are equal within each split,
so sample-weighted overall equals the equal-length mean; retain both formulas rather than implicitly assume this.
Compare validation with original stage_8000.validation for every n and overall; classification accuracies
should match exactly, while CPU float64 versus GPU batch-reduction CE can differ by tiny rounding amounts.
Freeze tolerances before evaluation and list differences separately; do not change precision/samples/models until passing.
Mean per-sample answer_ce/EOS_ce should match original two-supervised-token loss definitions; necessary
position/mask checks may use small train/validation batches, without test inputs or new training.
