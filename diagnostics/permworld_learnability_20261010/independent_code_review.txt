2. Historical exclusion: first verify SHA values of the historical index and archdev data archive, then add all eight-member orbits of each historical development train/validation/test anchor. 3. Identical data and budgets: fixed n10,11,12, train 2048/length, validation 1024/length; encodings share underlying permutations, answers, orbit splits, and saved 8000×64 batch schedule. The generator randomly permutes the three lengths every three updates; all models reuse this schedule. 2048×3, batch64, and 8k yield approximately 83.3 average training-set passes per model; this is a combined development change, not encoding alone.

4. Genuine initialization: each architecture has a genuinely constructor-produced step0.pt with parameters and RNG saved; both encodings and four properties load the same architecture-specific parameter values, with parameter_hash recomputed at training entry and CPU checks. Initialization checkpoint, initial parameters, protocol, source version, data, and starting RNG are all bound into restoration checkpoints. No identical-weight claim is made across architectures.

5. Answer supervision: reuse the frozen causal shift in batch/loss. CPU checks independently compare CE at answer and EOS positions, check that other positions receive no gradients, and compare answer logits for full sequences versus prompt-only inputs. Training/validation answer metrics use full-vocabulary argmax; numeric-restricted accuracy is separate. EOS is teacher-forced on the true answer and cannot replace answer learning.

6. Gates: protocol fixes the 8k endpoint, with each model's equal-length mean answer accuracy ≥90%, weakest length ≥85%, gain over the training length mode ≥20pp, and EOS ≥99%; same-task×architecture encoding gaps must be ≤5pp both in mean and at every length. Gates use only identity-validation answers/NLL, with one fixed candidate, no Γ/Δ/CKA or test-score-based configuration selection. Report implementation still requires independent fixtures for equal weighting, training-mode provenance, and rejection of incomplete endpoints.

7. Restoration checks: each architecture×encoding has genuine continuous 0→32 and separate-process 0→16→32 runs, comparing parameters, optimizer, and RNG. Engineering outputs are separate from source-model directories and cannot pre-update source models. Insufficient budget for 32 updates now produces explicit budget_exhausted, not a false RNG/parameter mismatch. An existing continuous reference without a complete result prevents silent continuation; retries after engineering interruption must explicitly handle reference identity, not fabricate a “continuous” reference.

8. Two hours: driver creates one persistent start/deadline, unchanged on restoration; stop_updates_epoch is deadline−30s, and no new job starts after cutoff. Training checks cutoff every update; validation entry, every batch, and each actual forward require at least 5s remaining. Insufficient validation yields None and validation_missing_due_to_budget=True rather than incomplete scores. After the deadline, only safe state saving occurs; CPU-tree serialization avoids full GPU validation disguised as “separately timed cleanup.” Actual final GPU-batch time and saving overhead still need runtime audits; paper safeguards do not prove strictly zero overshoot.

9. Completion identity: completed.json is written only for source output=None, genuine step8k, and complete validation. Engineering overrides cannot create source completion files even if requesting 8k. Driver checks fixed-manifest run_id, step8000, protocol, source version, and data SHA rather than counting arbitrary engineering files. Partial2k/4k/interrupted updates cannot replace 8k endpoints. Completion counts and learning-gate success are separate fields.

10. Timing interpretation: new driver records shared actual wall clock; summed historical concurrent per-model loop elapsed values are not actual machine GPU-hours. Historical throughput is only a proxy, not new “GPU-hours used”; measured serial runtime, restoration engineering, and validation all share the budget. Persistent epoch deadlines include idle time during pauses, a conservative constraint rather than precise GPU-kernel utilization.
