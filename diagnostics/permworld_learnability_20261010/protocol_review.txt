PermWorld 小型可学习性开发实验：独立协议与成本审查
日期：2026-10-10
审查范围：只读旧模型构造、训练配置、训练阶段耗时，以及保存的答案预测复算。未读取新几何指标，未训练，未修改旧冻结文件或 F17。本文是冻结前的建议，实际实验以 root 最终冻结协议为准。

一、建议固定一个方案，不在本轮增加候选网格

保留四个性质 descents / recoils / peaks / valleys，两种原 token 编码 one_line / canonical_cycle，以及 Transformer / GRU 两种原 256 维、4 层结构。因此一个完整开发单元是 4×2×2=16 个模型。Transformer 仍为 8 头；GRU 保留现有四个单层 GRU 加显式层间 Dropout 的可恢复实现。两者参数量并不相同：旧 Transformer 3,240,448，旧 GRU 1,660,416；不能称为等容量架构比较。

本轮固定长度 n=10、11、12。这个选择减少序列负担、增加每长度更新曝光，并避开历史 n≤9 全集占用问题；它不是“这个窗口已经可学会”的证据。使用全新数据世界和真实新 step-0，不复用旧训练权重。两编码共享底层排列、完整变换轨道划分、答案、batch 索引、更新数；同一架构的两编码逐值复制真实初始化。跨架构不声称共享相同参数。

建议使用 root 提出的单方案 lr=1e-3、dropout=0，仍用原 AdamW / weight decay / betas / eps / 梯度裁剪、有效 batch=64 和原精度设置。若沿用余弦调度，建议将原 5% warmup 比例固定为 400/8000 更新，余弦最低学习率比例仍为 0.1。这个选择只是提高学习机会的开发方案，并不是已验证的最优配置。最终冻结时须明确调度，不能根据验证曲线临时改 warmup、终点、学习率或正则。

先跑到 2,000 更新，检查工程状态、学习进展和真实耗时；随后从同一检查点继续到固定 8,000 更新。2k 包含在 8k 内，不是 2k 后重新训练 8k。预定几何评价不参与方案选择，本审查也不建议在本轮筛选阶段计算 CKA。若第一完整单元达到预定学习门槛且预算允许，再用同一个冻结方案做一个新世界、新初始化的完整 16 模型复核单元。没有预算时应明确只完成一个开发单元。

不建议同时跑两个 Transformer 候选，再扩展到全部 GRU 并要求独立复核；在两小时硬预算下，候选成本会挤占最关键的完整覆盖和新世界复核。若 root 改为 Transformer 先行，应在训练前固定为缩减范围，报告中不能称四条件交叉实验已完成。

二、旧结果对长度选择的实际支持

encoding_readiness 独立读取旧 final-20k、n=10、identity validation 的缓存预测和标签（256 输入），复算并与原验证曲线核对：

                         one_line       canonical_cycle
Transformer recoils       98.828%             41.016%
GRU recoils               66.016%             37.109%
训练长度众数基线在这个验证集上的准确率为 38.281%。两种 cycle 条件只比该基线高 2.734pp / 低 1.172pp；配对输入抽样标准误约 4.08pp / 4.55pp。

因此，旧 n=10 的轮换编码并没有显示可靠的实用学习优势。缩短窗口不是一个已通过的可学习性结论。也不能据此断言模型只输出一个长度众数：cycle 与该单一众数预测的一致率仅 38.67% / 25.78%，非众数样本仍有一定正确率，但整体收益被其他样本的错误抵消。新实验应检查全部四性质、全部三长度，不用一个聚合分数掩盖 recoils 等弱单元。

复算证据保存在本目录 old_learning_diagnosis_length.csv、old_learning_diagnosis_summary.csv、old_learning_diagnosis_audit.json 和 old_learning_diagnosis.txt；旧测试成绩只能作为旧描述性诊断，不能用来选择新协议。

三、数据与学习质量指标

建议新世界每长度 train=4,096、validation=1,024；最终独立测试的规模在冻结时固定（例如每长度 1,024）。验证使用 identity 输入和完整词表答案 argmax，不使用数字范围内重归一化的准确率作为通过门槛。分别报告答案 NLL、完整词表答案准确率、EOS 准确率；答案与 EOS 联合 loss 不能替代答案学习指标。训练长度众数只由训练答案确定，固定后用于验证/测试。

三长度等权汇总；同时完整展示每个模型的逐长度结果。1,024/长度时，单长度 90% 准确率的普通二项抽样 95% 半宽约 1.84pp，三长度汇总约 1.06pp。这是量级说明，输入共享及轨道依赖仍需保留；不是 16 个独立任务分布的统计保证。若实际数据可用性不足，必须在训练前记录缩减，不能按观察结果调整验证样本。

历史排除、完整轨道去重、train/validation/test 互斥、新复核世界与首世界互斥，都须在准备阶段审计。不仅排除直接排列，还须排除协议中的变换轨道。n=10..12 是否有足够未用轨道必须实际盘点，不能仅凭 n! 大就假定无泄漏。

建议把下面门槛用作“可以进入后续编码几何解释”的开发资格条件，而不是统计显著性或等价性结论：

1. 每个模型三长度等权完整词表答案准确率 ≥90%，且每长度 ≥85%；EOS ≥99%。
2. 每个模型相对训练长度众数的归一化答案收益 (Acc−Baseline)/(1−Baseline) ≥0.80。基线分母接近零时按预定规则标记无法评价，不临时换指标。
3. 同一 task×architecture 下，两编码三长度等权准确率差 ≤3pp、任一长度差 ≤5pp。该条件仅支持近似相同任务掌握的开发资格，不构成正式等价性检验。
4. 若需要讨论架构交互，再检查同一 task×encoding 的跨架构差是否 ≤5pp；否则保留结果但不能把几何差异单独解释为架构机制。

这些数值是明确、较严格的协议建议；root 应在任何新成绩揭示前固定最终标准。达到答案准确率门槛后，置信度与答案 NLL 差异仍需完整报告；准确率相近并不等于输出分布或内部计算相同。验证每长度至少 1,024 输入主要是提高学习资格判断精度，不是给开发实验增加“确认性”标签。

使用 train=4,096×3、batch=64 时，8k 更新对应每源模型约 512,000 样本曝光、约 41.7 次平均数据遍历。旧 train=4,096×21、20k 更新约 14.9 次遍历。因此新方案同时改变学习率、Dropout、长度范围和单位数据曝光。若它成功，只能说明这个冻结开发配置可学习，不能从本轮拆出某个改变的单独因果贡献。

四、筛查、淘汰与早停规则

2k 阶段首先检查真实参数更新、有限 loss/梯度、答案位置与 loss mask、真实 step-0 哈希、两编码配对初始化、保存恢复约束和实际壁钟。NaN/Inf、无实际更新、监督位置错误、数据泄漏或恢复失败应立即停下并报告工程失败；不得通过延长训练来遮蔽。

不建议把“2k 尚未达到 90%”作为淘汰规则。旧 cycle 任务可能学习慢，2k 的低分尚不足以排除 8k 能学会。固定每 1k 更新验证；若 loss 仍下降且预测完成整个 8k 清单符合预算，则继续到固定终点。

本轮最简洁的规则是固定 8k 终点，不按某个条件较早达到门槛就单独停训。若必须设置学习无效的提前淘汰，应在冻结前明确共同规则，例如 1k→2k 答案验证 NLL 改善 <0.02 nats、验证准确率 ≤长度众数+5pp、训练答案 NLL 同期也几乎未改善，三个条件同时满足才触发。这个阈值仍可能误淘汰较慢学习者，故优先使用它作为警示，而不是默认自动终止。

任何提前终止都应在相应 task×architecture 的两编码共同更新点处理，不能让一个编码获得更多监督。不得依据 Δ、Γ、CKA、层、正确/错误配对收益或预期论文方向淘汰模型。终点有弱任务时，完整保留 16 个学习结果，整单元不通过“充分学习/相近掌握”资格；不能事后只选择学得好的任务、长度或架构。

五、两小时实际 GPU 壁钟的成本审查

旧完整 16×20k 共 320,000 源更新，训练阶段实际壁钟为 10,038.25s（167.30min）。各模型 loop elapsed 合计约 30,045.51s，但模型并发且包含重叠验证/保存，不能把这个总和当作本机实际 GPU 壁钟。

以旧完整阶段的整体吞吐粗估，平均约 31.88 源更新/s：
  16×2k 筛查：32,000 更新，约 16.73min；
  16×8k 完整单元：128,000 更新，约 66.92min；
  两个 16×8k 单元：256,000 更新，约 133.84min，已超过 120min，尚未加入新检查。

这些只是旧吞吐下的条件估算。缩短到 n10..12 很可能更快，但不能按序列长度线性缩放：模型并发、CPU、padding、保存、验证和固定 overhead 都会影响实际速度。必须用真实新训练的 2k 阶段校准；零学习率计时不能取代。

GPU 预算应是所有新开发进程共享的实际占用壁钟上限 7,200s，不是各模型耗时之和，也不是 CUDA kernel 计时之和。训练、GPU 验证、恢复检查及 GPU 被占用时的保存开销全部纳入。CPU-only 准备若已释放 GPU可另列，但不能把占用期间等待 IO 从预算中扣掉。保持预定并发和 batch，不根据某种编码成绩更好改变资源分配。

建议在总预算里至少预留 900s 用于最终学习验证、必要审计、停止和产物整理，训练/验证主体最多 6,300s。要在这部分完成两个 8k 单元，整体至少需 40.63 更新/s（含相应阶段开销），较旧吞吐快约 27.5%。首单元 2k 阶段需约 ≤787.5s 才有按同速率完成两个单元的初步希望；若预测乘 1.2 安全系数，则需 ≤656.3s。这个公式不保证随后速度相同，应在每个共同 checkpoint 重新检查剩余预算。

实际执行建议：
  A. 新世界/新初始化单元：固定全 16 模型，2k→8k；2k 不另加到 8k。
  B. 仅 A 满足全部学习资格，且剩余预算 ≥1.2×A 的实测完整阶段耗时+最终保留时间时，才启动第二新世界/新初始化完整 16 模型单元；仍固定 8k。
  C. 否则停止并交付单单元可学习性结论和未完成复核的原因。不自动增加候选、扩展更新、补训弱任务或开展几何实验。

若 2k 实测预测连单个完整单元都无法在硬上限内完成，应在共同检查点记录预算停止，而不是运行到超过两小时再报告。新世界复核不得只做最有利的一两组；若 root 希望缩减复核范围，必须在成绩揭示前另行冻结缩减清单，并如实命名其覆盖范围。

六、成功后的允许解释与停止边界

首单元只回答：同一新底层数据与真实初始化配对下，这个固定小模型配置能否在两种编码和两种架构中充分学习这四个性质。第二新世界/初始化单元若完成，回答这个可学习性资格是否能独立复现。两个单元仍不足以建立普遍架构结论，不能把它们当作八个独立数学关系。

成功后可以保留冻结检查点供下一次明确授权的编码几何实验使用；本轮不按几何挑选模型，不自动算新的 Γ/CKA，不自动启动正式清单、GroupWorld、零空间、有限域、GELU 组合或更大模型。本轮结束于固定开发清单、学习结果、计时审计与停止记录；旧 PermWorld 诊断、旧编码开发和 F17 结果/发布产物保持不变。
