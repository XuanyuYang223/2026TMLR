PermWorld small learnability development experiment: independent protocol and cost review
Date: 2026-10-10
Review scope: read-only inspection of historical model construction, training configurations, training-stage timing, and recomputation from saved answer predictions. No new geometry metrics, training, changes to historical frozen files, or F17 edits. These are pre-freeze recommendations; actual experiments follow the root's final frozen protocol.

I. Fix one scheme rather than adding a candidate grid this round

Retain descents/recoils/peaks/valleys, original one_line/canonical_cycle token encodings, and original width-256 four-layer Transformer/GRU structures. A complete development unit therefore has 4×2×2=16 models. Transformer retains 8 heads; GRU retains the restorable four single-layer GRUs with explicit inter-layer Dropout. Parameter counts differ: historical Transformer 3,240,448 and GRU 1,660,416; this is not an equal-capacity architectural comparison.

Fix n=10,11,12. This reduces sequence burden, increases update exposure per length, and avoids historical exhaustive occupation at n≤9; it does not establish learnability of this window. Use a fresh data world and genuine new step-0, without historical training weights. Both encodings share permutations, full transform-orbit splits, answers, batch indices, and update counts; within architecture, both copy genuine initialization value by value. No shared parameters are claimed across architectures.

Use the root's proposed single scheme lr=1e-3, dropout=0, retaining original AdamW/weight decay/betas/eps/gradient clipping, effective batch=64, and precision settings. If cosine scheduling is retained, fix the original 5% warmup ratio at 400/8000 updates and minimum learning-rate ratio at 0.1. This development choice increases learning opportunity; it is not a validated optimum. Freeze scheduling explicitly, without changing warmup, endpoint, learning rate, or regularization based on validation curves.

First run 2,000 updates to check engineering status, learning progress, and actual timing; then continue the same checkpoints to fixed 8,000 updates. 2k is included in 8k, not an additional 8k restart. Prespecified geometry evaluation does not select the scheme; this review does not recommend computing CKA during screening. If the first full unit meets learning gates and budget permits, use the same frozen scheme for a complete fresh-world/fresh-initialization 16-model verification unit. Without budget, explicitly report only one development unit.

Do not run two Transformer candidates, then expand all GRUs and require independent verification; under a two-hour hard budget this crowds out complete coverage and fresh-world verification. If the root chooses Transformer-first execution, freeze the reduced scope before training and do not report the four-condition cross as completed.

II. Actual support from historical results for length selection

encoding_readiness independently read historical final-20k, n=10, identity-validation cached predictions and labels (256 inputs), recomputed scores, and checked against historical validation curves:

                         one_line       canonical_cycle
Transformer recoils       98.828%             41.016%
GRU recoils               66.016%             37.109%
The training-length-mode baseline achieves 38.281% on this validation set. The two cycle conditions are only 2.734pp above / 1.172pp below that baseline; paired input-sampling standard errors are approximately 4.08pp / 4.55pp.

Thus historical n=10 cycle encoding shows no reliable practical learning advantage. A shorter window is not an established learnability result. Nor does this show models output only one length mode: cycle predictions agree with that single-mode predictor only 38.67% / 25.78%; some nonmode answers are correct, but errors elsewhere offset overall gains. The new experiment must examine all four properties and all three lengths, without hiding weak cells such as recoils behind aggregate scores.

Recomputation evidence is saved in old_learning_diagnosis_length.csv, old_learning_diagnosis_summary.csv, old_learning_diagnosis_audit.json, and old_learning_diagnosis.txt in this directory; historical test performance is only a historical descriptive diagnostic, not a basis for selecting the new protocol.

III. Data and learning-quality metrics

Recommend train=4,096 and validation=1,024 per length in the new world; freeze final independent test size, e.g. 1,024 per length. Validation uses identity inputs and full-vocabulary answer argmax, not numeric-renormalized accuracy as a passing gate. Separately report answer NLL, full-vocabulary answer accuracy, and EOS accuracy; joint answer/EOS loss cannot replace answer-learning metrics. Training length modes use training answers only and remain fixed for validation/test.

Aggregate three lengths equally while showing every model's per-length results. With 1,024/length, an ordinary binomial sampling 95% half-width at 90% accuracy is approximately 1.84pp per length and 1.06pp across three lengths. These indicate scale only; shared inputs and orbit dependence remain, not a statistical guarantee over 16 independent task distributions. Insufficient data availability must be recorded as a reduction before training, without adapting validation samples to results.

Historical exclusion, full-orbit deduplication, train/validation/test disjointness, and disjointness between the new verification and first worlds must be audited during preparation. Exclude transformation orbits in the protocol, not only direct permutations. Adequate unused orbit counts at n=10..12 require actual inventory, not an assumption from large n!.

Recommended development qualification gates for later encoding-geometry interpretation, not statistical significance or equivalence conclusions:

1. Each model's equal-three-length full-vocabulary answer accuracy ≥90%, each length ≥85%, and EOS ≥99%.
2. Each model's normalized gain over the training length mode, (Acc−Baseline)/(1−Baseline), ≥0.80. Near-zero baseline denominators follow a prespecified unevaluable rule, without switching metrics.
3. Within task×architecture, encoding accuracy gaps ≤3pp in the equal-three-length mean and ≤5pp at any length. This supports approximately matched mastery as a development qualification, not a formal equivalence test.
4. To discuss architecture interactions, also check cross-architecture gaps ≤5pp within task×encoding; otherwise retain results without attributing geometry differences solely to architectural mechanisms.

These are explicit, relatively strict protocol recommendations; the root must fix final standards before any new scores are revealed. After accuracy gates pass, fully report confidence and answer-NLL differences; similar accuracy does not mean identical output distributions or internal computation. At least 1,024 validation inputs per length primarily improves qualification precision, not a “confirmatory” label for development.

With train=4,096×3 and batch=64, 8k updates provide approximately 512,000 sample exposures and 41.7 average data passes per source. Historical train=4,096×21 and 20k updates give approximately 14.9 passes. Thus the new scheme jointly changes learning rate, Dropout, length range, and per-datum exposure. Success would show learnability of this frozen development configuration, not identify any change's individual causal contribution.

IV. Screening, elimination, and early-stopping rules

At 2k, first check actual parameter updates, finite loss/gradients, answer positions/loss masks, genuine step-0 hashes, paired encoding initializations, restoration constraints, and wall clock. NaN/Inf, no updates, supervision-position errors, leakage, or restoration failure should stop immediately as engineering failures, without concealing them through longer training.

Do not eliminate conditions merely for “not yet reaching 90% at 2k.” Historical cycle tasks may learn slowly; a low 2k score does not rule out learning by 8k. Validate every fixed 1k updates; continue to the fixed endpoint if loss still declines and the full 8k manifest is projected within budget.

The simplest rule is a fixed 8k endpoint, without stopping individual conditions as soon as they reach gates. Any learning-futility elimination requires a shared pre-freeze rule, such as 1k→2k answer-validation NLL improvement <0.02 nats, validation accuracy ≤length mode+5pp, and nearly unchanged training-answer NLL over the same interval, all three together. This may still eliminate slow learners incorrectly, so prefer a warning rather than default automatic termination.

Any early termination should occur at common update points for both encodings of task×architecture, without extra supervision for one encoding. Never eliminate by Δ, Γ, CKA, layer, correct/wrong-pair benefit, or expected paper direction. Retain all 16 learning results when endpoints include weak tasks; the whole unit fails “sufficient/matched mastery,” without selecting favorable tasks, lengths, or architectures afterward.

V. Cost review for two hours of actual GPU wall clock

The historical complete 16×20k stage has 320,000 source updates and actual wall clock 10,038.25s (167.30min). Summed model-loop elapsed time is approximately 30,045.51s, but concurrency and overlapping validation/saving mean this is not actual machine GPU wall clock.

Historical full-stage throughput gives a rough average of 31.88 source updates/s:
  16×2k screening: 32,000 updates, approximately 16.73min;
  16×8k complete unit: 128,000 updates, approximately 66.92min;
  Two 16×8k units: 256,000 updates, approximately 133.84min, already above 120min before new checks.

These are conditional historical-throughput estimates. Shortening to n10..12 likely speeds execution, but not linearly with sequence length: concurrency, CPU, padding, saving, validation, and fixed overhead matter. Calibrate using genuine new 2k training; zero-learning-rate timing cannot replace it.

The GPU budget should be a shared actual-occupancy wall-clock limit of 7,200s across new development processes, not summed model times or CUDA-kernel times. Include training, GPU validation, restoration checks, and saving while GPU resources remain occupied. CPU-only preparation after releasing GPU can be separate, but IO waits during occupancy cannot be deducted. Keep prespecified concurrency/batch settings without reallocating resources based on encoding scores.

Reserve at least 900s for final learning validation, necessary audits, stopping, and artifact organization, leaving at most 6,300s for core training/validation. Completing two 8k units there needs at least 40.63 updates/s including stage overhead, approximately 27.5% above historical throughput. The first unit's 2k stage must take ≤787.5s to offer preliminary hope at unchanged speed, or ≤656.3s with a 1.2 safety factor. This does not guarantee future speed; recheck remaining budget at each common checkpoint.

Practical execution recommendations:
  A. Fresh-world/fresh-initialization unit: all fixed 16 models, 2k→8k; 2k is included in 8k.
  B. Start a second fresh-world/fresh-initialization complete 16-model unit only if A meets every learning qualification and remaining budget ≥1.2×A's measured full-stage time plus final reserve; still fix 8k.
  C. Otherwise stop and report single-unit learnability and why verification remains incomplete. No automatic candidates, update extensions, weak-task retraining, or geometry experiments.

If measured 2k timing predicts even one full unit cannot fit the hard limit, record budget stopping at a common checkpoint rather than exceeding two hours. Fresh-world verification must not select the best one or two conditions; any reduced verification scope requires freezing before scores are revealed and accurate naming of coverage.

VI. Permitted interpretations after success and stopping boundary

The first unit asks only whether this fixed small-model configuration sufficiently learns four properties across both encodings and architectures with paired fresh data/genuine initialization. A second completed world/initialization unit tests independent repeatability of that learnability qualification. Two units still cannot establish universal architectural conclusions or count as eight independent mathematical relations.

After success, frozen checkpoints can support a later explicitly authorized encoding-geometry experiment. This round does not select models by geometry, automatically compute new Γ/CKA, start the formal manifest, GroupWorld, null-space, finite-field, GELU-composition, or larger-model work. It ends with the fixed development manifest, learning results, timing audits, and stopping records; historical PermWorld diagnostics, encoding development, F17 results, and release artifacts remain unchanged.
